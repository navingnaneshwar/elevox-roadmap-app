## 1. Executive Summary

Elevox is an AI-powered executive thought leadership coaching platform for CxOs. The platform guides executives through a 6-phase coaching journey, ghostwrites LinkedIn content, and manages an EA → Executive → Publish approval pipeline.

Sprint 1 delivered the authentication and data layer. Sprint 2 delivered the AI coaching sessions, brand brief generation, ghostwriting UI, and email notifications. **Sprint 3 completes the monetisation layer, hardens security, wires the remaining editorial pipeline features, and prepares the platform for production launch.**

## 3. Business Requirements

### BR-01 — Payments Must Be Live
**Priority:** Critical
**Description:** Users who click "Upgrade" on any plan must be redirected to a Stripe-hosted Checkout page. Successful payment must automatically update their plan and unlock the corresponding phases. Failed payments must trigger a notification.
**Acceptance:** Stripe test card `4242 4242 4242 4242` successfully creates a subscription and updates `profiles.plan` in the DB.

### BR-02 — Plan Access Must Be Server-Enforced
**Priority:** Critical
**Description:** Users must not be able to access paid coaching content by manipulating client-side state. The server must verify plan entitlement before serving AI responses.
**Acceptance:** A `starter` plan user calling the `mentor-chat` Edge Function with a Phase 3 component ID receives a 403 response.

### BR-03 — Editorial Pipeline Must Be End-to-End
**Priority:** High
**Description:** Content generated by the AI Ghostwriter must flow into the content calendar, be routable through the approval workflow, and be trackable to a publishing state.
**Acceptance:** A user can generate a draft in GhostwriterPanel → select it → see it appear in the content_calendar table with status `draft` → submit for EA approval → EA approves → status moves to `approved`.

### BR-04 — Production Errors Must Be Captured
**Priority:** High
**Description:** Any runtime error, API failure, or unexpected state must be logged to a central issue log with enough context to diagnose in production.
**Acceptance:** Issue log document exists, is updated within 24h of any error discovered, and includes RCA + fix.

### BR-05 — Roadmap Must Navigate to Coaching Sessions
**Priority:** Medium
**Description:** The Roadmap view shows all 24 phase components. Clicking any unlocked component must navigate the user directly to the coaching session for that component.
**Acceptance:** Clicking an unlocked component on the Roadmap routes to `/coach/:phaseId/:componentId`.

### BR-06 — Approval Workflow Must Be Stable
**Priority:** Medium
**Description:** The ApprovalWorkflow component has a React hook error causing cascading re-renders. This must be fixed before production.
**Acceptance:** No React warnings or errors in console when viewing ApprovalWorkflow. Approval simulation completes without page freeze.

### BR-07 — Codebase Must Pass Lint Before Deployment
**Priority:** Medium
**Description:** `npm run lint` must complete with zero errors.
**Acceptance:** `npm run lint` exits with code 0.

## 4. Out of Scope (Sprint 4+)

The following are explicitly deferred and must not be built in Sprint 3:

- LinkedIn / social platform posting API integration
- Real-time analytics dashboard (follower counts, engagement rates)
- WhatsApp / Slack notification channels
- Admin dashboard for internal team
- Password change / account deletion settings page
- PDF progress export
- Phase interconnection (Phase 01 brand data auto-populating Phase 02 prompts)
- AI-generated profile photo recommendations
